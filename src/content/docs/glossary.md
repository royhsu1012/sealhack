## 一、資料與任務的基本詞

### 特徵(Feature / 變數 / X)
用來做判斷的線索。預測房價時,「坪數、屋齡、地段」就是特徵。
表格資料裡,**每一個欄位就是一個特徵**。

### 目標(Target / Label / y)
你要預測的東西。房價預測裡的「價格」。
- 有 target 的資料 = **有標資料**(train)
- 沒有 target 的資料 = **無標資料**(test)

### 樣本 / 列(Sample / Row / Instance)
一筆資料。表格裡的一行。

### 訓練集 / 測試集(Train / Test)
- **train**:有答案,拿來學習
- **test**:沒答案,你要預測的對象,主辦方拿它算你的分數

### 任務型別
| 型別 | 意思 | 例子 |
|---|---|---|
| **二分類** | 預測是/否 | 客戶會不會流失 |
| **多分類** | 預測屬於哪一類 | 這是貓/狗/鳥 |
| **迴歸** | 預測一個數字 | 房價是多少 |
| **排序** | 預測優先順序 | 推薦哪些商品 |

### 類別不平衡(Class Imbalance)
正例只佔 1%、負例佔 99% 這種情況。模型會偷懶全猜「否」也有 99% 正確率,所以這時**不能用準確率當指標**。

## 二、訓練與驗證(最重要的一組)

### 模型(Model)
一個把「特徵」轉換成「預測」的數學函式。你可以把它想成一個學生。

### 訓練 / 擬合(Train / Fit)
把有答案的資料餵給模型,讓它調整內部參數,直到預測儘量接近答案。

### 預測 / 推理(Predict / Inference)
把新資料餵給訓練好的模型,得到答案。

### 過擬合(Overfitting)⭐
模型把訓練資料「背」下來了,包含裡面的雜訊,導致換一批資料就失靈。
**症狀**:訓練分數極高,驗證分數很差。
**這是機器學習的頭號敵人。**

### 欠擬合(Underfitting)
反過來,模型太笨,連訓練資料都學不好。比較少見。

### 泛化(Generalization)
模型在「沒見過的資料」上表現好的能力。這才是真正的目標。

### 驗證集(Validation Set)
從訓練資料裡切出來、假裝自己沒答案的一小塊,用來評估模型。

### 交叉驗證(Cross Validation, CV)⭐
把資料切成 K 份(通常 5 份),輪流拿其中 1 份當驗證集、其餘當訓練集,做 K 次。
**為什麼重要**:比單次切分穩定得多,是你在沒有正解的情況下唯一能信的成績。

### 折(Fold)
交叉驗證切出來的每一份。「5-fold CV」= 切 5 份。

### OOF(Out-Of-Fold Predictions)⭐⭐
交叉驗證過程中,每一筆訓練資料被「當作驗證集」時得到的那個預測值,拼成完整一份。
**為什麼重要**:
1. 它是誠實的成績單(每筆預測都來自沒看過它的模型)
2. 它是後續整合的原料 —— 沒有它就不能做 hill climbing / stacking

### 切分策略
| 名稱 | 用在什麼時候 |
|---|---|
| **KFold** | 一般情況,隨機切 |
| **StratifiedKFold** | 分類任務,確保每折的正負例比例一致 |
| **GroupKFold** | 同一個使用者/病人的資料不可以同時出現在訓練和驗證 |
| **TimeSeriesSplit** | 時間序列。永遠「用過去預測未來」,絕不能隨機切 |

### 資料洩漏(Data Leakage)⭐
訓練時不小心用到了「預測當下不該知道的資訊」。
**常見來源**:未來資訊、目標編碼沒在 fold 內做、ID 編號本身帶有答案順序。
**症狀**:CV 分數高得不合理,一上線就崩。

### 隨機種子(Seed)
控制隨機性的編號。固定 seed = 每次跑結果一樣,實驗才能互相比較。
框架要求所有實驗共用同一個 seed 和同一組 fold,原因就是這個。

### 超參數(Hyperparameter)
模型訓練前你要自己設定的旋鈕,例如樹的深度、學習率。
**調參(Tuning)**= 找最好的旋鈕組合。
注意:調參的收益通常遠小於特徵工程,不要一開始就花時間在這。

## 三、評估指標(Metric)

指標決定你的所有戰術,**每場比賽第一件事就是搞懂指標**。

### 分類用

| 指標 | 白話 | 特性 |
|---|---|---|
| **準確率 Accuracy** | 猜對幾成 | 類別不平衡時會騙人 |
| **AUC (ROC-AUC)** | 模型把正例排在負例前面的能力 | 只在乎**排序**,不在乎絕對機率。0.5 = 瞎猜,1.0 = 完美 |
| **LogLoss** | 懲罰「很有自信但答錯」 | 在乎機率準不準,需要校準 |
| **Precision / Recall** | 精確率:抓出來的有幾成是對的<br>召回率:該抓的抓到幾成 | 兩者互相拉扯 |
| **F1** | Precision 和 Recall 的調和平均 | 需要搜尋最佳閾值 |

### 迴歸用

| 指標 | 白話 | 特性 |
|---|---|---|
| **RMSE** | 均方根誤差 | 對大錯誤懲罰重,怕離群值 |
| **MAE** | 平均絕對誤差 | 對離群值寬容 |
| **MAPE** | 百分比誤差 | 目標接近 0 時會爆炸 |

### 閾值(Threshold)
分類模型輸出的是機率(例如 0.73),要變成「是/否」得設一條線。
預設 0.5 通常不是最好的,**應該在 OOF 上搜尋最佳閾值**。

### 校準(Calibration)
讓模型輸出的「0.7」真的代表「70% 會發生」。
用 AUC 評分時不需要;用 LogLoss 時很重要。

## 四、特徵工程(Feature Engineering)

### 編碼(Encoding)= 把文字類別變成數字

| 方法 | 做法 | 注意 |
|---|---|---|
| **Label Encoding** | 每個類別給一個編號 | 樹模型可用,線性模型會誤解成有大小順序 |
| **One-Hot Encoding** | 每個類別開一個 0/1 欄位 | 類別太多會爆炸 |
| **Frequency Encoding** | 用「出現次數」代替類別 | 便宜好用 |
| **Target Encoding** | 用「該類別的目標平均值」代替 | 很強,但**極易洩漏**,必須在 fold 內計算 + 平滑 |

### 聚合特徵(Aggregation)
按某個鍵分組後算統計量。例:每個使用者的「平均消費金額」、「消費次數」、「金額標準差」。
**進階技巧**:算完之後,再做「這筆金額 ÷ 該使用者平均金額」這類比值,通常比原始聚合值更有訊號。

### 互動特徵(Interaction)
把兩個特徵組合。例:`身高 / 體重` = BMI。
樹模型學不好除法和比值,**手動餵給它效果很好**。

### 缺失值(Missing Value / NaN)
資料沒填的格子。處理方式:填平均數/中位數、填一個特殊值、或讓模型自己處理(LightGBM 支援)。
**注意**:「有沒有缺失」本身有時就是重要訊號,可以另外開一個欄位記錄。

### 特徵重要性(Feature Importance)
模型認為哪些特徵有用的排名。
- **Gain**:預設的演算法,會**高估高基數特徵**,不要盲信
- **Permutation Importance**:把某欄打亂,看分數掉多少。更可靠但較慢
- **Null Importance**:把 target 打亂當基準線,只保留明顯贏過基準的特徵

### 標準化 / 正規化(Standardization / Normalization)
把數值縮放到相近範圍。
- 線性模型、神經網路:**必做**
- 樹模型:**不需要**(樹只看大小順序)

## 五、模型家族

### GBDT(Gradient Boosting Decision Tree)梯度提升樹
一堆很淺的決策樹接力,每棵新樹專門修正前面所有樹累積的錯誤。
**表格資料的長期霸主。** 三個主流實作:

| 名稱 | 特點 |
|---|---|
| **LightGBM** | 最快,首選起手式 |
| **XGBoost** | 老牌穩定 |
| **CatBoost** | 類別特徵多的時候常最強,預設參數就很好 |

### 隨機森林(Random Forest)
一群獨立的深樹各自投票。比 GBDT 弱一些但很穩,不易過擬合。

### 線性模型(Linear / Logistic Regression, Ridge, Lasso)
只能畫直線/平面。單獨用很弱,但因為「犯錯的方式」和樹模型完全不同,**在整合裡價值很高**。
- **Ridge / Lasso**:加了正則化(防過擬合的懲罰項)的線性迴歸

### 神經網路(Neural Network / MLP)
多層運算堆疊。**MLP** = 最基本的全連線網路。表格資料上通常打不贏 GBDT,但一樣提供多樣性。

### KNN(K 最近鄰)
看最像的 K 個鄰居怎麼答。很樸素,但在整合裡偶爾有驚喜。

### SVM / SVR / SVC
支援向量機。用數學技巧畫出複雜的分界線。資料量大時很慢。

### TabPFN(Tabular Prior-data Fitted Network)
2025 年後的新物種。它已經在海量合成資料上預訓練過,你把資料喂進去,它**幾乎不用訓練**就直接給預測。
中小型資料(5 萬筆以內)上表現非常強。屬於「基礎模型 / Foundation Model」。

### AutoML(如 AutoGluon)
自動幫你試各種模型和組合的工具(k-fold bagging 產 OOF、多層 stacking、加權集成)。
2025 年 AutoGluon 已有以極低算力擊敗人工精調集成奪冠的實例——所以它不是「弱但方便」,
而是「不做人工特徵能到哪」的**誠實錨點**:你的人工投入要能贏過它才算數(見框架 §4.0)。

## 六、整合(Ensemble)

### 整合 / 融合(Ensemble / Blending)
把多個模型的預測合起來。
**核心原理**:模型 A 和 B 如果犯**不同的錯**,合起來錯誤會互相抵消。
所以**模型之間的差異性,比單一模型的分數更值錢**。

### 平均(Averaging)
最簡單的整合。
- **算術平均**:直接平均機率
- **Rank 平均**:先把預測轉成名次再平均。**用 AUC 評分時通常比算術平均好**
- **加權平均**:表現好的模型給高權重

### Hill Climbing(爬山法)
自動找最佳權重組合的方法:從最強的模型開始,反覆嘗試「加入某個模型、給多少權重」,只保留讓 OOF 分數上升的動作,直到無法再進步。

### Stacking(堆疊)
再訓練一個「第二層模型」,輸入是第一層各模型的 OOF 預測,讓它學會「什麼情況下該信誰」。
- 第二層模型叫 **Meta Model / Stacker**
- **關鍵防洩漏**:第二層必須用和第一層完全相同的 fold 切分

### Pseudo-labeling(偽標籤)
用最強的模型去預測無標資料(通常是 test),把預測結果當成「假答案」加回訓練集,重新訓練。
- **軟標籤(Soft Label)**= 用機率(0.83)而非硬答案(1),資訊更多、雜訊更少

### 知識蒸餾(Knowledge Distillation)
用一個強大但笨重的模型(老師)的輸出,去教一個輕巧的模型(學生)。
在競賽裡,可以把整個整合的知識濃縮排一個新的單模型。

### Seed Averaging(多種子平均)
同一組設定,換 10~100 個不同隨機種子各跑一次再平均。穩定且通常更準。

## 七、競賽專有詞

### Leaderboard(LB)排行榜
- **Public LB**:比賽期間看得到的分數,只用了一小部分 test 資料
- **Private LB**:比賽結束才揭曉,用剩下的 test 資料,**這才是最終名次**

### Shake-up(跳水)
比賽結束時名次大洗牌。原因幾乎都是有人過度擬合 public LB。
**防範方式**:迭代決策以 CV 為準(小 public LB 的危險在反覆使用的累積過擬合,見框架 §13),最終提交選一個 CV 高分 + 一個穩健方案。

### Adversarial Validation(對抗驗證)
訓練一個分類器去區分「這筆資料來自 train 還是 test」。
- 分不出來(AUC≈0.5)→ 兩者同分布,可放心隨機切
- 分得很清楚(AUC>0.8)→ 有分布漂移,要找出是哪些特徵造成的並考慮丟棄

### 分布漂移(Distribution Shift)
train 和 test 的資料長得不一樣。會造成「CV 很好但實戰失靈」。

### Baseline(基線)
最簡單的可行方案,用來當比較基準。任何新做法都要贏過它才有意義。

### Submission(提交)
交上去的預測檔案。多數比賽可以選 2 個作為最終計分對象。

### Notebook / Kernel
Kaggle 上的線上程式筆記本,附免費 GPU。

## 八、工具與函式庫

| 名稱 | 用途 |
|---|---|
| **pandas** | Python 處理表格資料的標準工具 |
| **NumPy** | 數值運算基礎,`.npy` 就是它的檔案格式 |
| **scikit-learn** | 通用機器學習工具箱,切 fold、算指標都靠它 |
| **Polars** | 比 pandas 快很多的新一代替代品 |
| **cuDF / cuML** | pandas / scikit-learn 的 GPU 加速版,幾乎不用改程式碼 |
| **CuPy** | NumPy 的 GPU 版 |
| **PyTorch** | 寫神經網路用 |
| **Optuna** | 自動調超參數 |

### GPU 加速為什麼重要
競賽的核心競爭力是「你能跑多少次實驗」。同樣的實驗 CPU 跑 2 小時、GPU 跑 5 分鐘,一天下來實驗次數差 20 倍以上。

## 九、學習路徑建議

如果你想邊做專案邊補基礎,按這個順序補最有效率:

1. **pandas 基本操作** — 讀檔、篩選、groupby、merge。這是 80% 的日常工作
2. **過擬合 + 交叉驗證** — 這兩個概念想通了,你就有了判斷力
3. **決策樹 → 隨機森林 → GBDT** — 理解一棵樹怎麼分裂,後面全通
4. **評估指標** — 特別是你正在打的比賽用的那個,要能手算
5. **特徵工程套路** — 聚合、編碼、互動,靠實作累積直覺
6. **整合** — 最後再學,因為它需要前面的 OOF 基礎

**不用一開始就懂的**:神經網路內部原理、梯度下降數學、正則化的推導。這些晚點補不影響你打比賽。
