**幻覺不是最大的危險,「流暢地執行錯誤的方向」才是。** AI 能流暢地寫程式碼,但它寫什麼取決於你怎麼問。不會診斷題型的人,會讓 AI 用隨機 KFold 切時間序列——AI 會流暢地做出一個 CV 漂亮、實戰歸零的方案,而且不會告訴你錯了。

本站教的是那一層:**五問診斷 → 確定軌道 → 才讓 AI 生成程式碼 → 用 OOF 協議驗證它。** LLM 越強,「怎麼問對、怎麼驗證」這一層越值錢,不會被模型進步淹沒。

差異化資產:**每一條方法論主張都附一支可重跑的驗證實驗**。12 條核心主張全數通過文獻 + 沙盒雙驗證(含 1 個官方反例),並用鐵達尼真提交拿到第一個真實排行榜數據點——內部 CV 對真實 LB 系統性樂觀 0.06~0.09,正是方法論自己預測到的。

## 怎麼用本站學

給有 Python 基礎、還沒打過比賽的人。照這個順序,約 3–4 週能獨立完成一場表格賽:

1. **學會診斷**——先做[五問路由](/workflow/0-diagnose/):模態 → 任務 → 指標 → test 切法 → 是不是 code 賽。回答完這五題,技術方案就定了 80%。**這一步先於任何模型。**
2. **跟著 workflow 打一場真的比賽**——[讀題](/workflow/0-diagnose/) → [鎖 CV](/workflow/1-validate/) → [基線](/workflow/2-baseline/) → [特徵](/workflow/3-features/) → [集成](/workflow/4-ensemble/) → [提交](/workflow/5-submit/)。workflow 就是課程,配一場當月 Kaggle Playground 邊做邊學。
3. **卡住時查地圖**——不懂某個概念,去[詞彙表](/glossary/)或[學習地圖](/maps/learning/)(它會告訴你這個概念的前置是什麼、學成的標誌是什麼)。小樣本題另看[小樣本守則](/workflow/small-n/)。
4. **自己重跑驗證,不要背**——[主張登錄表](/claims/)每條方法論主張都連到一支可下載的腳本。**不要照抄別人的方案**,在你自己的切分與算力下重跑一次,親眼看到數字,信念才是你的。
5. **看一個完整範例**——[鐵達尼案例](/cases/titanic/)把上面六階段完整走一遍,示範方法論如何得到一個誠實的分數、並預測到自己的排行榜衰減。

> **驗證而非記憶**:本站不要你背結論。每條主張都能重跑,連被推翻後修訂的原始結論都保留為修訂史——方法論被實驗打過臉而且誠實改了,這才是可信的來源。
