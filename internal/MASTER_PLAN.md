## 〇、定位句(v1.1 新增,一切文案的源頭)

> **先學會診斷,再讓 AI 動手。**
> 這是 AI vibecoding 之前的方法論層:AI 能流暢地寫程式碼,但它寫什麼取決於你怎麼問。
> 不會診斷題型的人,會讓 AI 用隨機 KFold 切時間序列——AI 會流暢地做出一個
> CV 漂亮、實戰歸零的方案,而且不會告訴你錯了。
> **幻覺不是最大的危險,「流暢地執行錯誤的方向」才是。**
> 本產品教的是:五問診斷 → 確定軌道 → 才讓 AI 生成程式碼 → 用 OOF 協議驗證它。

此定位的戰略價值:LLM 越強,「怎麼問對、怎麼驗證」這一層越值錢,不會被模型進步淹沒。

## 一、已定案的決策

| # | 決策 | 理由 |
|---|---|---|
| D1 | 產品方向 = **C 陪跑系統**(不是內容站、不是純工具站) | 免費教學供給過剩;稀缺的是「卡住時被接住」與完成率 |

| D10 | 方法論核心紀律 = OOF 落盤協議 + 實驗記錄表 + 共用 fold/seed | 一切整合與迭代的地基 |
| D11 | **身份 = 教練**,權威來源 = 系統嚴謹度,不是個人戰績 | v1.1 定案。網站本身就是資歷證明,品質門檻按此執行 |
| D12 | **語言 = 繁體中文先行**,i18n 路由第一天配置、/en/ 預留、英文內容 Phase 0 後再補 | 雙語內容維護成本翻倍;結構先行、內容後補 |
| D13 | 網站定位 = 靜態方法論展示,**互動功能一律進 backlog** 等 Phase 0 資料 | 守住「不要先寫產品」的紀律 |

## 二、風險與對策(v1.1 新增)

| 風險 | 內容 | 對策 |
|---|---|---|
| R1 合規 | Kaggle 禁止隊伍外私下分享程式碼,違者可能整批取消成績 | 社群規範明文:cohort 內**只分享方法與診斷,不分享程式碼**;程式碼討論一律引導至 Kaggle 公開討論區或各自完成 |
| R2 信任 | 教練無個人戰績,使用者會問「你什麼牌?」 | 以框架嚴謹度與公開透明代替獎牌;網站品質即資歷。選項:Phase 0 前自己公開打一場(時程 +1 月,待定) |
| R3 替代品 | 「為什麼不直接問 ChatGPT/Claude」 | 定位句正面回答:本產品在 AI 之前的診斷層,教的是怎麼問對與怎麼驗證 |
| R4 內容過期 | 比賽結束內容作廢 | 三層內容架構(D5) |
| R5 天花板 | 繁中市場小 | i18n 結構預留,內容穩定後翻譯成本極低(交給 LLM 批次完成) |

## 三、核心方法論(濃縮)

**競賽勝負 = 可信的 CV × 實驗吞吐量 × OOF 資產複利**

- 五問路由:模態 → 任務 → 指標 → test 切法 → code/prediction 競賽
- 階段:讀題(0.5d)→ 鎖 CV+首提交(1d)→ 多樣化 baseline(1d)→ 特徵迭代(50%)→ 整合(25%)→ 收尾(3d)
- 算力階梯:探索(子樣本/單折)→ 驗證(全量5折)→ 收斂(多seed/大整合),上階梯前先校準代理
- 資源分配定律:
  - 增益 ≈ b·log(實驗次數);加速 s 倍 = 時間延長 s 倍
  - 最佳化預算上限 = 剩餘時間 × (1 − 1/s)
  - 代理實驗判定:ρ² > 成本比 就用(早期幾乎永遠成立)
  - 例外:突破性假設不服從 log 定律,要保留高風險預算;code 競賽是懸崖不是曲線

## 四、產品架構(目標態)

```text
診斷器(5問) ──路由──> 軌道卡(T1/T3/T4:CV策略+指標+陷阱+模板)
                              │
用戶按軌道推進 ──產出──> OOF池 + 實驗記錄(進度即資產)
                              │
卡關偵測 ──定位──> 學習地圖節點(L0~L3-2)──> 補課內容
                              │
資源計算器 ──建議──> 現在該做什麼(優化/代理/直接跑)
```

護城河 = 「知道你在做什麼(軌道)+ 知道你缺什麼(節點)」的交叉 + 「AI 之前的診斷層」定位。

## 五、執行計畫

### Phase -0.5|方法論網站(★已上線 sealhack.com,2026-08-25)
- Astro + Tailwind,12 頁,`npm run build` 零錯誤零警告;研究(validation/)內嵌前端(public/validation + 主張表連結)
- 內容 = 拆分後的方法論 + 主張登錄表(元件讀 src/data/claims.json)+ 鐵達尼六階段案例 + 真提交 L3 數據
- ✅ 已部署:Cloudflare Workers 靜態資產 + sealhack.com(www 301 轉向);剩教學層強化(見「七、教學設計」)
- 用途:Phase 0 招募門面 + 教材 + 教練資歷證明

### Phase 0|Concierge MVP(網站上線後 3 週)
- 招 10 人(有 Python 基礎、沒打過比賽)
- 工具:Notion(軌道內容+進度表)+ Discord(卡關救援,自己人肉當偵測器)
- 繫結當月 Kaggle Playground,帶完整場:診斷→首提交→特徵迭代→整合→收榜
- **社群規範(R1):只分享方法與診斷,不分享程式碼**
- **要收集的資料:卡關點分布(在哪步、卡多久、什麼原因)、完成率、每人求救次數**
- 內容最小集:T1 軌道卡 + L1 三節點(過擬合/CV/OOF)+ run_experiment 模板

### Phase 1|驗證與決策(Phase 0 後 1 週)
- 完成率 ≥ 60% → 繼續;< 40% → 修流程重跑一梯
- 用卡關分布決定:哪些救援可自動化、哪些內容要補、診斷器要不要自動分析資料

### Phase 2|產品化(第 2–3 個月)
- 只自動化 Phase 0 證明高頻的部分
- 優先序:軌道內容頁 → 進度/實驗記錄 → 診斷器 → 卡關偵測
- 待決問題此時必須拍板:
  - **Q1 程式碼在哪跑**(Kaggle Notebook / 平臺 / 本地)→ 決定能否驗證進度 ★最關鍵
  - Q2 要不要支援 code 競賽的推論限制教學
  - Q3 診斷器輸入:手動填答 vs 上傳資料自動分析
  - Q4 卡關偵測訊號:時間停滯 / 主動求救 / 提交失敗

### Phase 3|擴張(第 4 個月起,視留存資料)
- 加軌道(T2 多分類 → T9 排序)、加 L3-1 整合節點
- 英文版內容(D12)
- 資源計算器、Successive Halving 模組產品化
- 影像/NLP(L4)只在表格路徑留存證明後才考慮

## 八、教學設計(讓網站從「參考」變「會教」)

教學命題:**先學會診斷,再讓 AI 動手**。對象:有 Python 基礎、沒打過比賽(D2)。

**學習者旅程(網站要支撐的六步)**:
1. 懂命題(診斷優先)→ 首頁 → 2. 學會診斷(五問)→ 0-diagnose → 3. 跟著 workflow 打一場真賽(做中學)→ workflow 八頁 →
4. 卡在概念時跳去看解釋 → glossary / 學習地圖 → 5. 靠「自己重跑驗證腳本」建立信念(不是背)→ claims 腳本 → 6. 畢業:能獨立完成一場比賽。

**三個教學支柱**:
- **診斷優先**:入口是五問,不是模型。
- **做中學**:workflow 就是課程,配一場當月 Playground 真賽走完;鐵達尼案例是完整範例。
- **驗證而非記憶**:每條主張附可重跑腳本,學習者自己跑一次建立信念(方法論§9「不要照抄別人方案,自己重跑驗證」)。

**完整性缺口與對策(依投報排序;原則:只加內容與連結,不加互動,守憲法)**:

| # | 缺口 | 對策 | 狀態 |
|---|---|---|---|
| A | 缺「如何用本站學」的入口 | 首頁加學習路徑(新手照著走) | ✅ 本輪 |
| C | 驗證腳本未被框成練習 | claims/case 加「自己動手驗證」框 | ✅ 本輪 |
| B | 兩張地圖未在需要時交叉連結(護城河) | workflow 頁加輕量「前置/延伸」連到 glossary + 學習節點 | 選配,漸進 |
| E | 缺前置/難度標示 | 學習地圖已有資料(前置、學成標誌),可標 sidebar badge | 選配 |
| F | 缺自我檢核 | 學習地圖節點的「驗證方式」就是自我檢核題,可整理成一頁 | 選配 |
| D | 只有一個案例 | 每月綁一場 Playground 真賽產新案例 | 接 Phase 0(需競賽規則) |

**不做**:互動診斷器、進度追蹤、帳號——這些是 Phase 2 產品化的事,等 Phase 0 卡關資料再決定(守「不要先寫產品」)。
